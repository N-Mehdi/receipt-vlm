# receipt-vlm

Extract receipts and French invoices from an image to JSON with
[Qwen3-VL-2B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct) fine-tuned with QLoRA
on a single Kaggle T4.

## Problem

Small vision-language models read documents well but do not follow a target schema: the base model
invents keys, writes addresses and dates in its own format, and sometimes loops until the token
limit. The goal is a compact model that returns valid JSON in a fixed schema for two document types:

- **Receipts**: [CORD v2](https://huggingface.co/datasets/naver-clova-ix/cord-v2) (Indonesian
  receipts, 800 train / 100 test).
- **French invoices**: 1200 synthetic invoices generated by this repo (Faker, 6 HTML templates,
  light augmentation) with consistent annotations: Luhn-valid SIRET, matching VAT number,
  HT + TVA = TTC. 50 of the 100 test invoices use two templates never seen in training.

## Results

Test sets, greedy decoding, fp16, at most 1024 new tokens. F1 is the micro F1 over
(field path, normalized value) pairs; exact match requires every field to be right.
Brackets give 95% bootstrap intervals (1000 resamples of documents).

| Test set | Model | Valid JSON | Exact match | Field F1 | Truncated |
|---|---|---|---|---|---|
| CORD (100) | zero-shot | 0.89 | 0.00 [0.00, 0.00] | 0.351 [0.322, 0.381] | 11% |
| | fine-tuned | 0.99 | **0.35** [0.26, 0.45] | **0.832** [0.789, 0.873] | 0% |
| Invoices (100) | zero-shot | 0.99 | 0.13 [0.07, 0.21] | 0.891 [0.866, 0.912] | 0% |
| | fine-tuned | 1.00 | **0.63** [0.53, 0.72] | **0.979** [0.972, 0.985] | 0% |
| seen templates (50) | fine-tuned | 1.00 | 0.72 [0.58, 0.84] | 0.984 [0.975, 0.991] | 0% |
| unseen templates (50) | fine-tuned | 1.00 | 0.54 [0.40, 0.68] | 0.974 [0.963, 0.985] | 0% |

Latency at batch size 1 on a T4 (fp16, adapter merged, 20 documents per set):

| Test set | Mean | p95 | Generated tokens/s | Peak GPU memory |
|---|---|---|---|---|
| CORD | 5.8 s | 8.5 s | 18 | 4.5 GB |
| Invoices | 14.3 s | 19.4 s | 21 | 4.2 GB |

Training: one epoch on 800 CORD receipts and 1000 invoices, 4-bit NF4 base, fp16, LoRA r=16
(alpha 32) on the language model projections (17.4M parameters), 225 steps, 52 minutes.

## Limits

- **No real data.** Invoices are synthetic and no real invoice was used for training or testing.
  Scores on real scans, handwriting, multi-page or multi-rate VAT invoices are unknown.
- "Unseen templates" only changes the layout; the text distribution comes from the same generator.
- CORD fields that are rare in training (sub-items, `itemsubtotal`, `etc`) are still missed.
- On CPU the live demo takes one to three minutes per document.

## Usage

```bash
pip install -r requirements.txt && pip install -e .
python scripts/generate_invoices.py --out data/invoices
python scripts/evaluate.py --dataset cord --adapter N-Mehdi/qwen3-vl-2b-receipts-lora --out outputs/cord.json
python scripts/train.py --invoice-source data/invoices --hub-repo <user>/<repo>
```

API and live demo (CPU, the base model and the adapter are downloaded on first use):

```bash
docker build -t receipt-vlm-api .
docker run -p 8000:8000 receipt-vlm-api
curl -F file=@invoice.jpg "localhost:8000/extract?kind=invoice"   # kind: invoice or cord
pip install -r app/requirements.txt && pip install -e . && python -m app.app   # Gradio demo
```

The Kaggle notebooks in [notebooks/](notebooks/) clone this repo and run the same scripts.
